# M1 — Core agent loop, remote providers, chat UI

Status: **done** (2026-10-18). Everything below runs in this container except iOS builds and on-device
checks, which need the macOS CI job and real hardware.

## What shipped

| Area | Package / path | Highlights |
|---|---|---|
| Agent loop | `packages/sherpa_core` (`AgentRunner`) | ReAct loop; checkpoint after every transition and `resume()` after process death (re-runs only idempotent interrupted calls); bounded parallel tools; annotation-driven approvals with scoped/expiring grants; cancellation that keeps tool-call pairing valid; retry before first output; branching (regenerate, edit); refused turns never run tools; trust-boundary clause; data-egress audit |
| Context (early M3) | `packages/sherpa_core/lib/src/context` | Escalation ladder (elide → clear inputs → compact → truncate → handoff recommendation → hard stop), window-scaled thresholds, segment rules for append-only providers, summary schema v2, extractive + model summarizers, inspector with diffs/undo, handoff bundle v1. The app uses the ladder with the extractive summarizer |
| Networking | `packages/sherpa_net` | Spec-compliant SSE decoder, SSRF-safe URL policy, Retry-After/backoff, secret redaction |
| Providers | `packages/sherpa_providers` | Anthropic Messages (thinking replay byte-stable, prefix guard, model-family traits); OpenAI Chat with quirk profiles for llama.cpp, Ollama, LM Studio, vLLM, OpenRouter, DeepSeek, HF router; stateless OpenAI Responses; server detection; context-length discovery; tool-call repair; `createProvider` factory |
| Persistence | `packages/sherpa_data` | Drift on SQLite3MultipleCiphers (chacha20), fail-closed key handling, `DriftSessionStore`, `JsonDocumentStore`, migrations scaffold |
| Markdown | `packages/sherpa_markdown` | Incremental streaming parser (frozen blocks never re-parsed, ~60 µs/token) and renderer: code with highlighting + copy, tables, math, task lists; network images only on tap |
| App | `app/` | `material_ui` design system with contrast-checked tokens; adaptive shell (phone, tablet split view, foldables); onboarding to a first chat; provider settings with Keychain/Keystore keys and URL policy; privacy dashboard; chat with frame-coalesced streaming, reasoning region, tool cards, approval card/sheet, branch switcher, jump-to-latest, slash menu, model picker, context ring |

Early M2 work also landed: `packages/sherpa_hub` (Hub client, name parser, device-fit engine, download
planner) — see M2 notes when that milestone closes.

## How to verify

```sh
flutter pub get
tools/test_all.sh                                   # analyze + all suites
cd app && flutter build apk --debug --target-platform android-arm64
zipalign -c -P 16 -v 4 build/app/outputs/flutter-apk/app-debug.apk
```

Results at the M1 commit: core 117, data 175, hub 269 (+3 live, opt-in), net 13, providers 263,
markdown 149, app 196 tests passing; `dart analyze --fatal-infos` clean; debug APK builds and passes the
16 KB alignment check with `libsqlite3mc.so` bundled.

## Post-M1 review

An adversarial review (by area, then each finding independently refuted or confirmed) found 36 issues;
27 survived verification and all 27 are fixed with regression tests. The four high-severity ones:
repaired tool calls could run under an existing grant; untrusted MCP servers could skip approval by
declaring `readOnlyHint` + closed-world; a chat kept its old runner (old endpoint, old key) after its
provider was edited; and the composer's Stop/Send controls were unusable with a screen reader.

## Known gaps

- **Not verified here:** iOS build (macOS CI job), any physical device, VoiceOver/TalkBack.
- **Links** in replies show the full URL with "Copy link"; opening needs `url_launcher` (M6).
- **Summaries are extractive.** Model-written compaction needs the session's provider wired into the
  summarizer, together with the context inspector UI (M3).
- **Model switch** changes the model for future turns; the automatic handoff bundle on switch is M3.
- **Composer** has no attachments or dictation yet (M6).
- **Anthropic:** server-tool / unknown blocks are skipped rather than preserved; `file://` images are
  not inlined; no client-side image downscaling.
- ~~**OpenAI:** no idle timeout on streaming requests~~ — fixed after M1: every streaming provider has
  a 90 s idle timeout between chunks and a 10 min start timeout (configurable per provider).
- **Restored backups:** the DB key is device-only, so a database restored on a new device is moved
  aside and a fresh one created. Since M2 the file is also excluded from iOS backups natively
  (`BackupExclusion`), as it already was on Android (backup rules XML).
- ~~**Privacy dashboard** export/delete are stubs~~ — done in M3.
- English only.
- Debug APKs still package `libdartjni.so` for armeabi-v7a/x86_64 from a prebuilt plugin; release
  builds should be produced with `--target-platform android-arm64`.
