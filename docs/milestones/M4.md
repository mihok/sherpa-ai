# M4 — MCP client, OAuth, tool UX, approvals, tool budget

Status: **done** (2026-10-19), with the gaps listed below. Verified in this container against fakes and
real reference MCP servers; nothing here has run on a phone yet.

## What shipped

| Area | Package / path | Highlights |
|---|---|---|
| Client | `packages/sherpa_mcp` | Both protocol eras: the stateless 2026-07-28 era (`server/discover`, per-request `_meta`, `InputRequiredResult`, `subscriptions/listen`, POST-only Streamable HTTP with routing headers) and the session-based eras, chosen by a probe; SSE fallback; conformance tests against real servers |
| Auth | `packages/sherpa_auth`, `app/lib/services/mcp/auth` | OAuth 2.1: protected-resource and authorization-server discovery, issuer checks, dynamic client registration, PKCE (refuses servers without S256), `resource` parameter, RFC 9207 `iss`, step-up; browser via `flutter_web_auth_2` (Auth Tab / Custom Tabs, ASWebAuthenticationSession); redirect `io.github.mihok.sherpa:/oauth/callback`; consent sheet before every authorization; tokens only in the Keychain/Keystore |
| Server manager | `sherpa_mcp/lib/src/router/server_manager.dart` | Lazy connect, jittered reconnect, health, redacted per-server logs, listen on foreground / stop on background, connectivity-aware |
| Tool hygiene | `sherpa_mcp/lib/src/router/hygiene.dart` | Definition pins (SHA-256 over canonical JSON); new tools from untrusted servers and every changed tool are quarantined with a readable diff; injection scanner (hidden characters, instruction overrides, shadowing, credential paths, markdown images…); flagged or untrusted tools get destructive/open-world defaults |
| Router and budget | `sherpa_mcp/lib/src/router/mcp_tool_router.dart` | Stable namespaced names; per-session enablement; per-model budgets (remote / local / tiny) with a frozen deferred mode and BM25 `tool_search` + `call_tool` proxies; result limits; schema normalizer and argument validation |
| Approvals | `sherpa_core/lib/src/tools/approval.dart`, `app/lib/features/chat` | Grants bound to server + tool + definition hash; untrusted servers never get "Always"; repaired or name-corrected calls to non-read-only tools ask once and record nothing; calls cut off by the output limit never run; prompts show the real target behind `call_tool`; taint gating once untrusted content is in context |
| Built-in servers | `sherpa_mcp/lib/src/servers` | In-process MCP framework with memory-notes and device-facts servers |
| App | `app/lib/features/mcp` | Tools & servers settings; add by URL, QR, `sherpa://mcp/add` deep link (always confirmed) or the official MCP Registry (v0.1 API, remote servers only); server detail (declared hints, findings, tool switches, trust, resources, prompts, console); tool review; remembered approvals; per-chat tool sheet; slash commands from MCP prompts and `@` resource mentions in the composer |

## How to verify

```sh
cd packages/sherpa_mcp && dart test
cd packages/sherpa_auth && dart test
cd app && flutter test test/features/mcp test/services/mcp
```

The real-server tests in `app/test/services/mcp` and `packages/sherpa_mcp/test` skip when the reference
servers are not available locally.

## Known gaps

- **Not verified on devices:** OAuth browser flows, deep links, QR scanning. `flutter_web_auth_2` 5.1.0
  has no UIScene support on iOS (6.0, still alpha, adds it).
- **Sign-in interrupted by process death** must be restarted.
- **No CIMD and no manual client-id entry:** authorization servers without dynamic registration fail with
  a plain-language reason.
- **Registry entries** that need secret headers or URL variables can't be added yet.
- **Elicitation and sampling** are declined until M5.
- **Router session state** (deferred-mode segment) is not persisted; the first turn after a restart
  recomputes the tool list.
- A deep link that arrives during onboarding is dropped; servers can't be renamed in the UI.
