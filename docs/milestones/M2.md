# M2 — Hugging Face directory, device fit, downloads, on-device inference + optimization

Status: **done** (2026-10-19), with the gaps listed below. The llama.cpp path is verified end to end on
the Linux host with a real model; the Android build is verified up to the APK; nothing has run on a phone.

## What shipped

| Area | Package / path | Highlights |
|---|---|---|
| Hub client | `packages/sherpa_hub` | Search with filters, repo trees at a pinned commit, GGUF header reader (sizes every variant from one read), model-name parser (128-row corpus), device-fit engine (Fits / Tight / Won't fit with the reason and the largest context that fits), download planner (shards, projector pairing, MLX support files) |
| Directory UI | `app/lib/features/models` | Browse with format/size/license/task/tool-use filters and trusted quantizers; uncensored fine-tunes hidden and counted; model detail with license, gating steps, scan status, variants with fit badges; recommended variant preselected |
| Downloads | `app/lib/services/downloads` | Resume with Range, re-resolve on expiry, SHA-256 off the UI isolate, atomic install, Wi-Fi only by default, one large file at a time; the HF token never reaches background_downloader (Hub-origin files fetched in-process) |
| Library | `app/lib/features/models` | Installed models, disk usage, GGUF import (refuses pickles and removed quant types), "Use in chat", performance lab entry |
| Engine | `native/engine`, `native/llama` | `sherpa_engine`: versioned 39-function C ABI over pinned llama.cpp (struct_size forward compatibility, poll-based events with backpressure, prefix KV reuse, state files with identity header, n-gram / draft / MTP speculation, no-alloc memory dry run, bench); Android arm64 build with CPU variants loaded by name, KleidiAI, 16 KB alignment |
| Dart side | `packages/sherpa_inference` | FFI host on background isolates; Android out-of-process host (`:inference` service, Binder + Pigeon, credit-based backpressure, crash forensics from ApplicationExitInfo, restart backoff); `LlamaCppProvider`; lifecycle with admission from engine dry runs, one warm model, memory-pressure and background policies; scheduler (foreground > tool follow-up > background); autotune; persistent prefix cache |
| Platform providers | `packages/sherpa_litert`, `packages/sherpa_apple_ml` | LiteRT-LM and Gemini Nano (Android); MLX and Apple Foundation Models (iOS) |
| App wiring | `app/lib/services/inference` | Built-in `local` provider over the library, picker section with fit badges, exact token counting, warming context manager, model-written summaries at background priority, autotune as idle work, crash report and live-crash context downgrade |
| Performance lab | `app/lib/features/perf` | Device/engine/tuning overview with a live panel, benchmarks with history, A/B tester that names a winner only beyond noise, apply/reset overrides |

## How to verify

```sh
cd packages/sherpa_inference && SHERPA_ENGINE_LIB=<host libsherpa_engine.so> \
  SHERPA_TEST_MODEL=<gguf> flutter test          # unit + real-engine integration
cd app && flutter test test/features/models test/services test/features/perf
cd app && flutter build apk --debug --target-platform android-arm64
```

`packages/sherpa_inference/tool/build_host_engine.sh` builds the host library; `native/llama/build_android.sh`
builds the Android libraries into `native/llama/out/android/jniLibs`.

## Known gaps

- **Not verified on devices:** the Android `:inference` service (Binder, bind flags, exit records),
  GPU/NPU backends, every Gemini Nano path, all of iOS (MLX, Foundation Models, the engine xcframework).
- **iOS background downloads** continue only the current 256 MB segment while suspended.
- **Android downloads** run each segment as WorkManager work, which Android stops after about 9 minutes;
  the plugin re-queues it and resumes with a Range request. User-initiated data transfer jobs (Android 14+,
  no such limit) are not used yet.
- **Wi-Fi only** on Android waits for a connection Android counts as Wi-Fi: with a VPN up a download may not
  start. After 30 s on screen the download says so and offers mobile data for the rest of that download;
  turning the VPN off, or Pause then Resume, tries it again.
- **Fit** for MLX and LiteRT is an estimate from file sizes; card fit on search results is a heuristic.
- **Draft models** for speculative decoding are measured in the lab; LoRA is applied only at load.
- **Vision** needs an engine built with mmproj support (`SHERPA_ENGINE_MTMD`).
- Prefix state is saved on chat switch and backgrounding, not after every turn.
